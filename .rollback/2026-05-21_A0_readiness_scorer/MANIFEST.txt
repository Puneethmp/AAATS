ROLLBACK BASELINE — 2026-05-21 A.0 readiness scorer fix
========================================================

Scope:
  Single-file fix to production_readiness/metrics_aggregator.py.
  Targets two arithmetic bugs surfaced by 2026-05-22 NO-GO investigation:
    1. Maximum Drawdown reported -781.0% (real: -13.06% from risk_engine_state.json)
    2. Infrastructure Uptime reported 0.0% (real: >99% per heartbeat with cycle_count=71+)

  Bug A — lines 127-136: cumulative-pnl curve uses max(peak, 1.0) as denominator,
  producing multi-hundred-percent drawdown when the cum-pnl peak is tiny. Also
  computes drawdown from realized-only pnls curve, not the canonical equity peak
  recorded by risk/engine.py in data/state/risk_engine_state.json.

  Bug B — lines 210-211, 226: heartbeat_reliability is a binary
  `1.0 if heartbeats else 0.0`, with no freshness check. Stale heartbeats vote
  100% healthy. Missing heartbeats collapse uptime to 0%.

  Fix path:
    - Prefer canonical peak/last_equity from data/state/risk_engine_state.json
      when present; fall back to a clamped pnl-curve calc if not.
    - Use monitoring.heartbeat_monitor.is_alive(market, max_age_seconds=120)
      per-market and average the fresh-count instead of binary OR.
