# C5b Funding-Arb Halted — 2026-05-15

## Halt date
2026-05-15

## Status
HALTED in `trading/live_paper_runner.py` (registration block commented out).
Container `aaats-paper-crypto` rebuilt against the commented version; C5b no longer
executes per cycle.

## Reason
C5b's BUY/SELL recording schema is structurally asymmetric:
- BUY records per-leg notional ($25 — spot leg only)
- SELL records round-trip notional ($50 — spot + perp combined)

This is documented in `docs/known_issues/2026-05-15_state_db_delta_snapshot.md` and
in the project memory note "C5b latent $25 WARN bomb". The 2026-05-15 share-equality
assertion (post-INSERT SELL/BUY delta detector) will WARN on every C5b close with
delta ≈ $25. On the operator's Telegram alert channel this is indistinguishable from
a real correctness bug from any other strategy and pollutes the signal.

The unified-ledger spec freeze (pending answers to Q1–Q4) will decide whether C5b
should record per-leg or round-trip and harmonise the schema globally. Patching
the schema before that decision is rework.

## Re-enable conditions (ALL must hold)
1. Unified-ledger spec Q1–Q4 answered and approved.
2. Dual-leg accounting decision made (per-leg vs round-trip) and applied to
   `trading/funding_arb.py` BUY+SELL recording paths.
3. A SELL is recorded in a sandbox/canary cycle and the share-equality assertion
   does NOT fire (post-INSERT delta < $0.01).


## Expected assertion behaviour if re-enabled WITHOUT schema fix
On the first natural C5b SELL the post-INSERT share-equality assertion will emit
a WARN to the Telegram channel with:
- `delta ≈ $25.00` (12dp precision)
- `strategy=C5b` (funding_arb)
- assertion path: SELL notional - sum(prior BUY notional) per `symbol+strategy_id`

This is alert pollution, not a correctness signal. Real bugs in other strategies
would surface as similarly-shaped alerts; halting C5b keeps the channel signal-clean.

## Trading volume foregone
Negligible. C5b position cap is $50/symbol × 2 symbols = $100 max deployment at
$110 starting equity. Funding entry threshold has fired infrequently in practice
(only one BUY recorded since 2026-05-12 tune of ENTRY_RATE_THRESHOLD).
